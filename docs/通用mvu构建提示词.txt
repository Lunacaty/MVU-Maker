1.主角:基础包括名称,状态,所处地点,所属势力,身份,外貌.可能包括:根据世界观添加HP,MP,灵根,修为,境界,元素亲和,宗门等等

2.技能:当前世界观下,主角的技能,一个record,key为技能名,value为object{描述;可能包括:威力,特殊效果,品级,类型(比如主动?被动?),属性等}

3.性癖:主角的性癖,一个record,key为性癖名,value为object{描述,起源,高潮次数}

4.交际:出现的NPC,一个record,key为角色名,value为object{好感度,状态,性格,关系,态度,心声,简介,战力(境界/等阶),动向,外貌,性癖(string就行,不必record),身份;可能包括:技能(同样是record),HP等等与主角一样的其他属性}

5.事务:主角当下需要完成的事情,一个record,key为事务名,value为object{名称,委托方,内容,奖励,风险,状态}

6.动向:[完全]不和主角相关的,也不是主角正在参与的,只能是发生在世界中的事件,需要主角自行参与,极少直接影响主角.包括两个属性:事件数,事件集(一个record,key为事件名,value为object{时间,地点,类型(阴谋|天灾|争乱|政变|其他),描述});更新备注:事件数不需要更新,由状态栏的js代码计算后写回mvu,LLM可以读不能写

7.小总结:近期发生的事情,包括:小总结TK总数,小总结集(一个record,key为string小总结时间点,value为string小总结内容)每次回复在小总结集生成一条20~80字小总结;更新备注:小总结TK总数不需要更新,由状态栏的js代码计算后写回mvu,LLM可以读不能写.公式:TK总数=小总结总字数*0.6.

8.大总结:长期记忆,record类型,key为string大总结时间范围,value为string大总结内容.更新备注:每当小总结TK总数超过500时,清空所有小总结,将其转化为一条大总结记录整个时间范围内发生的事情

9.全局信息:包括时间;更新备注:务必要提供一个具体时间,以供小总结生成时参考

10.(可能)战斗:包括时间,地点,缘由,预测胜者,参与者(record,key:参与者名字,value:object(战斗状态,阵营).可能会有HP,MP);备注:虽然变量中,战斗的参与者不跟踪技能等信息,但是状态栏绘制时要展示相关的其他信息,也就是要从结构中的交际或主角中获得同名NPC/主角信息,补充缺失的技能,好感度,心声等.也就是说,战斗发生时,主角之外的参与者必须先注册到交际中

11.小圈子:主角与交际中的友人的交流传信,类似朋友圈/QQ空间的动态;类型为record,key为动态标题,value为object(发布者,时间,正文,评论集(array,元素为object{评论者,内容,回复对象(可为空)))};更新备注:每次回复清空旧小圈子的动态数据,然后加入7个动态,1个主角自己发的关于本次回复事件的吐槽/看法/想法或分享,2个NPC关于主角本次回复遭遇的看法,2个NPC自己的生活分享,2个NPC之间的交际互动分享;只有好感度大于60或对主角态度友善的NPC才能在小圈子中发动态,如果NPC数量充足,每个动态的回复至少需要4人评论,最多有8条评论;里面的动态将会影响"人际"中NPC的"动向"

12.持有:记录主角持有的东西,类型为record,key:物品名,value:object{数量,描述,品质}

13.成就:记录主角取得的成就,关键发展节点与称号等,类型record(key:成就名,value:object{时间,类型,品级,描述,加成})PS.在状态栏中的Tab中,不写为成就,而是"往昔"

【整体视觉风格】

主题基调：暧昧、华丽、神秘。

核心配色：默认主题: 以深邃的“神秘紫”（如暗紫、黑紫渐变）为主背景色，以“华丽金”（如暗金、亮金、香槟金）为边框、文字高亮和副色调。副主题:可选绿,蓝,粉,红等颜色为主背景色,副色调不变

整体质感：使用 CSS 渐变、发光阴影（box-shadow）、玻璃拟态（半透明背景+高斯模糊）来凸显“华丽感”。绝不能显得简朴。

【全局布局与边框规则】

外层容器：整个状态栏只在最外层有一个明显、华丽的金色实体边框（可带有内发光）。

内层分割：状态栏内部的各个区域（上层、按钮栏、下层）之间没有任何空白间距（margin: 0），必须紧密贴合。各区域之间仅使用极细的半透明金色边框（如 1px solid rgba(255, 215, 0, 0.3)）隔开。

响应式设计：必须针对 PC端（宽屏，精致排版）和 移动端（手机，竖屏紧凑，适配触摸）编写两套适宜的 @media 响应式 CSS。

【区域设计详情】
顶层标题：

最上方居中渲染角色卡标题。字体需要华丽、具有艺术感，带金色文字发光效果（text-shadow）。

一、 核心上层区域（主角基础信息）：
不使用任何内部边框包裹单项，信息自然排布。

各类有上限的数值(比如HP,MP)单独占一行。格式为 XXX: [蓝色进度条 当前值/上限]。进度条需要有流光动态效果或好看的渐变色。

所在地与状(若有)：单独占一行，左右分布或并排展示。

财富与所属势力(若有)：在同一行展示。财富格式必须为 X [货币]，数字用金色高亮。

其他信息均需要合理布局,美观展示

二、 核心中层区域（导航标签栏）：

用于分隔上下层。这是一栏占满整个横向宽度的按钮组。

排版：由于按钮较多，必须分为两行展示（使用 CSS Grid 或 Flex Wrap），按钮之间没有任何空白间隙，仅用细边框分隔。

按钮内容：技能(或具体的能力类型变量,由世界观和具体变量结构决定)、交际、事务、动向、往昔(也就是变量里的成就)、性癖、战斗、总结, 圈子。

交互：点击按钮切换下方区域的内容，当前激活的按钮要有明显的“点亮/按下”金色高亮视觉反馈。

三、 核心下层区域（详情展示与卡牌区）：

容器设定：设定一个固定高度(单位为px)，当内容超出时，使用华丽定制的自定义滚动条（不要用浏览器默认的丑陋滚动条）。

折叠面板（Accordion）功能：在“交际”和“战斗”等信息复杂的标签页中，不要直接平铺所有角色技能。角色名旁边放置一个“查看技能”按钮。点击后向下平滑展开该角色的详细技能信息；再次点击可收回。允许多个条目同时处于展开状态。(再次强调技能是拟命名,实际结构不一定是技能,仅仅代表NPC的力量)

其他:

改和删按钮不要使用原生浏览器对话接口,自己绘制美观对话框

【动画细节要求】

状态栏的交互必须有丝滑的动画,禁止生硬跳变或瞬移.

折叠/展开动画: 状态栏默认折叠,点击标题栏展开时,内容区要有平滑的展开动画(如 max-height + opacity 过渡),收起时反向平滑收起.折叠指示符(箭头等)跟随状态变化.

导航标签栏 hover 动画: 鼠标移到 Tab 按钮上时,只做文字颜色/发光的动画,不要整体位移(整体位移会带动边框,显得凌乱).激活的按钮要有明显的"点亮/按下"金色高亮.

Tab 内容切换动画: 切换 Tab 时,新内容要有淡入+轻微上移动画(如 opacity + translateY,0.3~0.4s).注意切换时只播一次,轮询刷新时不要重复播放(否则会反复闪烁).

卡片 hover 细节: 鼠标移到内容卡片上时,卡片有轻微上移(1~2px)+金色边框发光过渡;卡片内的编辑✏️/删除❌按钮在鼠标移入卡片时才浮现(opacity 过渡),移出时隐藏.

展开/收起类功能(如"查看技能"折叠面板、交际卡片的"查看立绘"): 展开时要有平滑过渡动画,收起时平滑还原.展开态下轮询刷新不得打断动画.

查看立绘(交际卡片)(用户说需要角色立绘再看): 
- "查看立绘"按钮放在卡片右下角
- 点击后立绘从卡片右上角出现,动画为向左下角"放大"(transform: scale(0→1), transform-origin: top right)
- 出现过程中,卡片原有的信息向左缩入
- 卡片随立绘放大向下拉伸,腾出立绘展示空间
- 立绘尺寸需要较大,以便看清细节
- 卡片最终分成两个区域:左信息、右立绘(参考 card-split 双列 grid 布局)
- 立绘右上角可放 🔁 按钮切换多张立绘
- 动画全程丝滑,禁止立绘或信息瞬移

横向溢出: 内容区固定宽度,禁止出现横向滚动条;超出宽度用 overflow-x: hidden 裁剪,纵向超长用自定义美观滚动条.

【角色创建卡片要求】

角色创建卡片(开场时让玩家填写主角信息)单独实现,与状态栏共用同一套视觉风格(神秘紫+华丽金、玻璃拟态、金色边框).

内容: 名称(必填)、身份(可留空)、外貌(可留空)、偏好世界观多选(按钮式勾选,如修仙/西幻/都市/末世/科幻/都市异能/日式异世/武侠/古风宫斗等).

交互: 偏好世界观按钮点击切换选中态(金色高亮),可多选.确认创建按钮提交.

提交行为: 点击确认创建后,写入主角信息到 MVU 变量(stat_data 的 主角.名称/身份/外貌/偏好世界观 等,以及完整的初始结构含系统娘),然后创建用户消息并触发生成.

创建卡片中可附带说明区块(如难度与内容控制条目的使用说明),提示玩家前往世界书开关.
