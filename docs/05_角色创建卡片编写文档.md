# 05 · 角色创建卡片编写文档

> "角色创建卡片"是**开局让玩家捏人/设定主角**的交互界面：显示在开局楼层，
> 玩家填写或点选（姓名、性别、外貌、出身、属性分配、初始装备等），
> 提交后写入 MVU `stat_data` 变量，再触发 AI 正式开局。
>
> 本质：**一个放在开局消息里的可交互前端界面**，通过正则替换占位符呈现，
> 用 JS 把表单结果写进变量。**Electron 工具新增此功能 = 注入占位符 + 两条正则 + 一段 HTML。**

## 1. 工作原理

```
开局楼层（first_mes）
 ├─ 剧情引导文本
 └─ <CreateCardPlaceHolder/>          ← 占位符
       │  正则② markdownOnly 替换
       ▼
   交互式捏人 HTML（表单/分步向导）
       │  玩家填写 → 点击"开始"
       ▼
   JS: updateVariablesWith(stat_data ← 捏人结果)
       │  + 记录系统日志 + 隐藏创建卡片
       ▼
   玩家/触发 AI 回复 → 游戏开始
```

**两个关键动作**：
1. **呈现**：占位符 → HTML（正则替换，`markdownOnly`）
2. **写入**：JS 把玩家选择写进 `stat_data`（并标记"已创建"，防止重复捏人）

> 与状态栏的区别：状态栏是**持续显示**的只读面板；创建卡片是**一次性**的写表单。
> 因此创建卡片通常有"提交后把自己收起来"的逻辑（把容器隐藏或移除占位符）。

## 2. 占位符与正则配对

### 2.1 占位符约定

- 无内容占位符命名：`<PascalCaseName/>`，如 `<CreateCardPlaceHolder/>`、`<OpeningSelectUI/>`
- 占位符追加到**开局消息**（`data.first_mes`）末尾

### 2.2 两条正则（注入 `extensions.regex_scripts`）

```jsonc
// ① 对AI隐藏创建卡片 —— 占位符不进 AI 上下文
{
  "id": "<uuid>", "scriptName": "对AI隐藏创建卡片",
  "findRegex": "<CreateCardPlaceHolder/>",
  "replaceString": "",
  "placement": [2],
  "disabled": false, "markdownOnly": false, "promptOnly": true,
  "runOnEdit": true, "substituteRegex": 0
}
// ② 角色创建卡片 —— 前端替换成捏人界面
{
  "id": "<uuid>", "scriptName": "角色创建卡片",
  "findRegex": "<CreateCardPlaceHolder/>",
  "replaceString": "```\n<!doctype html>...捏人界面 HTML...\n```",
  "placement": [2],
  "disabled": false, "markdownOnly": true, "promptOnly": false,
  "runOnEdit": true, "substituteRegex": 0
}
```

### 2.3 如果 AI 也输出占位符

若想让 AI 在每轮也输出该占位符（从而让创建卡片"浮层"反复出现），需在世界书里要求 AI 输出，
但这通常不必要——创建卡片只出现在开局。

## 3. 方案 A：纯原生 JS 版（推荐）

> 与状态栏同理，Electron 工具直接生成**完整 HTML 文档**写入替换正则，零构建、零 CDN 依赖。

### 3.1 完整示例（分步向导 + 提交写变量）

````
```

<html lang="zh-CN">
<head>
<meta charset="utf-8">

<div class="creator">
  <h2>✨ 创建你的主角</h2>

  <div class="step">
    <label>姓名</label>
    <input id="c-name" maxlength="16" placeholder="输入主角名">
  </div>

  <div class="step">
    <label>出身</label>
    <div class="opt-row" data-act="origin">
      <div class="opt" data-val="冒险者">冒险者</div>
      <div class="opt" data-val="贵族">贵族</div>
      <div class="opt" data-val="平民">平民</div>
      <div class="opt" data-val="流民">流民</div>
    </div>
  </div>

  <div class="step">
    <label>初始状态</label>
    <div class="opt-row" data-act="state">
      <div class="opt" data-val="健康">健康</div>
      <div class="opt" data-val="轻伤">轻伤</div>
      <div class="opt" data-val="疲惫">疲惫</div>
    </div>
  </div>

  <div class="actions">
    <button class="btn-ghost" id="btn-reset">重置</button>
    <button class="btn-primary" id="btn-start">开始旅程</button>
  </div>

<script type="module">
const $ = (sel) => document.querySelector(sel);
const notice = $('#notice');
const picked = { origin: '冒险者', state: '健康' };

function esc(s) {
  return String(s ?? '').replace(/[&<>"']/g,
    c => ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c]));
}
function safe(fn) { try { fn(); } catch (e) { console.error(e); } }

// 选项高亮（事件委托）
document.querySelector('.creator').addEventListener('click', (e) => {
  const opt = e.target.closest('[data-act] .opt');
  if (!opt) return;
  const act = opt.parentElement.dataset.act;
  opt.parentElement.querySelectorAll('.opt').forEach(o => o.classList.remove('sel'));
  opt.classList.add('sel');
  picked[act] = opt.dataset.val;
});

$('#btn-reset').addEventListener('click', () => {
  safe(reset);
});
function reset() {
  $('#c-name').value = '';
  document.querySelectorAll('.opt').forEach(o => o.classList.remove('sel'));
  const first = document.querySelector('[data-act="origin"] .opt');
  if (first) first.classList.add('sel');
  picked.origin = '冒险者'; picked.state = '健康';
  notice.textContent = '';
}

$('#btn-start').addEventListener('click', async () => {
  const name = $('#c-name').value.trim();
  if (!name) { notice.textContent = '请先输入主角姓名。'; return; }

  await updateVariablesWith(vars => {
    _.set(vars, 'stat_data.主角.姓名', name);
    _.set(vars, 'stat_data.主角.状态', picked.state);
    _.set(vars, 'stat_data.主角.所在地', '新手村');
    _.set(vars, 'stat_data.主角.属性.力量', 10);
    // 记录系统日志（随变量发给 AI，让 AI 知道初始设定）
    const log = _.get(vars, 'stat_data.系统日志', []);
    log.push(`{{user}}创建了角色「${name}」，出身${picked.origin}，初始状态${picked.state}`);
    _.set(vars, 'stat_data.系统日志', log);
    return vars;
  }, { type: 'message', message_id: getCurrentMessageId() });

  // 创建完成：收起界面
  document.querySelector('.creator').innerHTML = '<p style="color:#f0d478">✅ 角色创建完成，旅途开始！</p>';
  notice.textContent = '';
});

$(errorCatched(() => { safe(reset); }));
</script>
</body>
```
````

### 3.2 关键点

- **写变量用 `updateVariablesWith` + `_.set`**（比 `getMvuData`+`replaceMvuData` 更稳）
- `getCurrentMessageId()` 只在消息楼层 iframe 可用——创建卡片正是消息楼层渲染，✅
- **提交后收起界面**（`innerHTML` 替换为完成提示），避免玩家反复改
- 用 `esc()` 转义一切插值，防 XSS
- 选项选择用**事件委托**（`closest('[data-act] .opt')`），避免逐个绑定

## 4. 方案 B：Vue 前端版

多步向导/复杂条件分支/进度条时用 tavern_helper_template + Vue。流程同 [04](04_状态栏编写文档.md) 方案 B：

1. `src/{Project}/界面/创建卡片/`（index.ts + index.html + App.vue + store.ts）
2. `store.ts`：`defineMvuDataStore(Schema, { type:'message', message_id: getCurrentMessageId() })`
3. 本地用 Live Server + `pnpm watch` 预览，发布走 jsDelivr CDN
4. `正则/角色创建卡片.html` 里 `$('body').load(...)` 加载 CDN 产物

提交逻辑与方案 A 相同（`updateVariablesWith` 写 stat_data + 系统日志）。

## 5. 提交与写变量

### 5.1 写入目标

捏人结果应写入 `stat_data` 的"主角"分组（与 schema 一致）。常用字段：

```jsonc
{
  "stat_data": {
    "主角": {
      "姓名": "玩家名",
      "性别": "男",
      "状态": "健康",
      "所在地": "新手村",
      "属性": { "力量": 10, "敏捷": 8, "魔力": 12 },
      "物品栏": { "铁剑": { "描述": "新手铁剑", "数量": 1 } },
      "性癖": []
    },
    "系统日志": [ "{{user}}创建了角色「...」" ]
  }
}
```

### 5.2 系统日志

把玩家操作写成 `{{user}}...` 文本追加到 `系统日志`，作为变量发给 AI：
- AI 知道变量变化**原因**（比如积分扣了、物品少了）
- 界面渲染时若在最新楼层则清空日志（防重复发送）

## 6. 捏人表单设计建议

| 项 | 建议 |
|----|------|
| 姓名 | 输入框 + 校验非空 |
| 出身/职业 | 单选卡片（opt 样式），备选 3~6 个 |
| 属性分配 | 滑块/输入，注意总和上限，写前钳制 |
| 初始物品/天赋 | 勾选卡（可多选） |
| 提交确认 | 二次确认弹窗（自绘 modal，勿用 confirm） |
| 重复进入 | 检查 `stat_data.主角.已创建` 标记，已创建则直接跳过向导 |
| 移动端 | 按钮最小 44px，可点区域够大 |

> **schema 一致性**：捏人写入的字段必须在 schema.ts 里定义（或用 `.prefault()` 兜底），
> 否则 zod 校验会剥离未定义字段或更新失败。

## 7. 与 MVU 初始化的配合

- **方式一（推荐）**：捏人界面写在开局楼层，`[InitVar]` 提供所有变量的**初始默认值**，
  捏人提交时用 `updateVariablesWith` **增量覆盖**其中"主角"相关字段。
- **方式二**：开局消息末尾用 `<initvar>` 块全量覆盖——但这样捏人界面拿不到"玩家已填"
  的前置状态，适合"捏人结果直接当初始值"。

> 注意执行顺序：MVU 初始化变量 → 开局楼层渲染（创建卡片可读默认值）→ 玩家提交覆盖。
> 如果创建卡片先于变量初始化执行，读取会拿到空值，需在 `init` 里
> `await waitGlobalInitialized('Mvu')` 或重试读取。

## 8. 常见错误

| 症状 | 原因 | 修复 |
|------|------|------|
| 创建卡片不显示 | 正则没配对 / 占位符不在 first_mes | 检查隐藏+替换两条正则；确认 `data.first_mes` 含占位符 |
| 提交后变量没变 | schema 未定义该字段被剥离 | 字段写入 schema（或 `.prefault()`） |
| 变量是字符串 | `z.number()` 遇字符串 | `z.coerce.number()` |
| 卡片反复出现 | 没做"已创建"标记/没收起 | 提交后 `innerHTML` 替换 + `已创建` 标记 |
| `getCurrentMessageId` 报错 | 在脚本 iframe 用 | 仅在消息楼层 iframe 用（创建卡片天然是） |
| 再次进入聊天卡片还在 | 跨聊天持久 | 检查 `stat_data.主角.已创建` 再做判断 |
