## 1. 角色卡文件格式

SillyTavern 的角色卡有两种承载形式：

| 形式 | 说明 | 判定 |
|------|------|------|
| **PNG** | 角色卡 JSON 以 `chara` 文本块（tEXt chunk）嵌入 PNG，图片本身是头像 | 文件头 `\x89PNG` |
| **JSON** | 纯 JSON 文本，无头像 | 以 `{` 开头，含 `spec: "chara_card_v2"` |

> 注意：JSON 角色卡的标准格式与"独立世界书"扁平格式不同。
> 判别：角色卡含 `spec` / `data` 字段；独立世界书含 `entries` 数组。

### 两者结构关系

```
PNG
 ├─ 头像像素数据（显示用）
 └─ chara 文本块 ──► 角色卡 JSON（与 .json 内容完全一致）
```

**Electron 工具的关键操作**：读 PNG 时用 `pngjs` 等库从 tEXt chunk 提取 `chara` → `JSON.parse`；
写 PNG 时把改好的 JSON 重新放回 `chara` chunk。**JS 写 PNG 必须注意正确的 CRC 计算**（见 [06](06_构建工具文档.md)）。

## 2. 角色卡 JSON 结构（chara_card_v2）

角色卡 JSON 分两层：**v1 壳**（兼容层）与 **v2 数据**（`data` 字段）。

### 2.1 v1 壳字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 角色名 |
| `description` | string | 角色描述 |
| `personality` | string | 性格摘要 |
| `scenario` | string | 场景设定 |
| `first_mes` | string | 开场白（主） |
| `mes_example` | string | 示例对话 |
| `creatorcomment` | string | 作者注释 |
| `tags` | string[] | 标签 |
| `talkativeness` | number | 话痨度 0~1 |
| `fav` | boolean | 收藏 |
| `create_date` | string | 创建时间 |
| `data` | object | **v2 数据（真实内容）** |
| `chat` | string | 当前聊天文件名（运行时） |
| `avatar` | string | 头像文件名（运行时，作唯一 id） |
| `json_data` | string | 原始 JSON 文本（运行时） |

### 2.2 v2 数据字段（`data`，Electron 工具实际改这里）

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 角色名 |
| `description` | string | 角色描述 |
| `character_version` | string | 卡版本号 |
| `personality` | string | 性格 |
| `scenario` | string | 场景 |
| `first_mes` | string | 主开场白 |
| `mes_example` | string | 示例对话 |
| `creator_notes` | string | 作者注释 |
| `tags` | string[] | 标签 |
| `system_prompt` | string | 系统提示词 |
| `post_history_instructions` | string | 历史后指令 |
| `creator` | string | 作者 |
| `alternate_greetings` | string[] | 备用开场白（第 0 个是主开场白的镜像） |
| `character_book` | object | **内嵌世界书** |
| `extensions` | object | **扩展区（正则、酒馆助手脚本都在这里）** |

### 2.3 `extensions` 扩展区（加 MVU/状态栏的落脚点）

```jsonc
{
  "extensions": {
    "talkativeness": "0.5",
    "fav": false,
    "depth_prompt": { "prompt": "", "depth": 4, "role": "system" },
    "regex_scripts": [ /* 正则脚本数组 */ ],
    "tavern_helper": {          // ← 酒馆助手扩展
      "scripts": [ /* 脚本数组：新版酒馆助手(JS-Slash-Runner)要求数组，元素含 name/content/enabled */ ],
      "variables": { /* 角色卡级变量 */ }
    }
  }
}
```

> **核心结论**：给角色卡加 MVU = 往 `data.extensions` 写 `regex_scripts` 和
> `tavern_helper.scripts`，往 `data.character_book` 加条目，往 `data.first_mes` 加占位符。

## 3. 世界书（World Book）

世界书是角色卡的"设定数据库"，运行时由关键词/位置策略决定哪些条目塞进 AI 上下文。

### 3.1 内嵌世界书结构（`character_book`）

```jsonc
{
  "name": "世界书名",
  "entries": [ /* v2DataWorldInfoEntry 数组（chara_card_v2 spec；ST 导入时 entries.forEach） */
    { /* 条目 0 */ },
    { /* 条目 1 */ }
  ]
}
```

### 3.2 条目字段（`v2DataWorldInfoEntry`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `keys` | string[] | 主要关键词（绿灯用） |
| `secondary_keys` | string[] | 次要关键词 |
| `comment` | string | 条目名（显示名） |
| `content` | string | **条目正文** |
| `constant` | boolean | 是否蓝灯（恒定激活） |
| `selective` | boolean | 是否绿灯（关键词激活） |
| `insertion_order` | number | 插入顺序 |
| `enabled` | boolean | 是否启用 |
| `position` | string | 插入位置（见下） |
| `extensions` | object | 位置/深度/概率等高级设置 |
| `id` | number | 条目 id |

### 3.3 激活策略（蓝灯 / 绿灯）

| 策略 | 说明 | 字段组合 |
|------|------|---------|
| **蓝灯 🔵 constant** | 只要满足"启用 + 激活概率"就恒定发送，不依赖关键词 | `constant: true, selective: false` |
| **绿灯 🟢 selective** | 必须在欲扫描文本中扫到 `keys` 任一关键词才激活 | `selective: true`，`keys` 非空 |
| 向量化 🔗 | 语义检索，一般不用 | `extensions.vectorized: true` |

**绿条款欲扫描文本的来源**（可开关）：用户输入、角色描述、角色性格、场景、深度提示词、作者注释等。

> **MVU 的变量列表/更新规则/输出格式条目全部用蓝灯**（保证每轮都发），
> `[InitVar]` 条目必须 `enabled: false`（只用来读初始值，不发送）。

### 3.4 插入位置（`position` + `extensions.position`）

条目的发送位置由 `position`（字符串）与 `extensions.position`（数字）共同决定。
数字枚举来自 SillyTavern `world-info.js` 的 `world_info_position`；ST 导入时优先读 `extensions.position`：

| position 字符串 | extensions.position | 含义 |
|-----------------|---------------------|------|
| `before_char` | 0 | 角色定义之前 |
| `after_char` | 1 | 角色定义之后 |
| `@D`（或 `before_author_note`） | 2 | 作者注释顶部（ANTop） |
| `@D`（或 `after_author_note`） | 3 | 作者注释底部（ANBottom） |
| `@D` | 4 | 按深度插入（`at_depth`），由 `extensions.depth` 指定插入到第几楼 |
| `@D` | 5 | 示例消息顶部（EMTop） |
| `@D` | 6 | 示例消息底部（EMBottom，勿用于 MVU 条目） |
| | 7 | `outlet`（已弃用） |

> ⚠️ 常见误区：`@D` 对应的数字是 **4（at_depth）**，不是 6。6 是 EMBottom（示例消息之后），
> 把 MVU 条目写成 6 会导致条目被塞到对话示例后面、位置完全错乱。

**MVU 各条目标准配置**（官方规范，`order` 统一 200）：

| 条目 | enabled | constant | extensions.position | depth |
|------|---------|----------|--------------------|----|
| `[InitVar]请勿打开` | **false**（必须禁用） | true | 4 (at_depth) | 4 |
| `变量列表` | true | true | 4 (at_depth) | 0 或 1 |
| `[mvu_update]变量更新规则` | true | true | 4 (at_depth) | 0 |
| `[mvu_update]变量输出格式` | true | true | 4 (at_depth) | 0（Gemini）/ 4（Claude） |

`extensions` 中的相关字段：

```jsonc
{
  "position": 4,          // at_depth（@D）
  "depth": 0,             // 插入深度（0 = 贴最新楼层）
  "role": 0,              // 0=system, 1=user, 2=assistant
  "order": 200,           // 同位置内排序
  "probability": 100,     // 激活概率
  "sticky": null,         // 黏性
  "cooldown": null,       // 冷却
  "delay": null,          // 延迟
  "display_index": 0
}
```

### 3.5 条目正文的 YAML / 结构化约定

条目正文是自由文本，但社区约定用 YAML 分段包裹：

```yaml
---
<character_basic character="系统娘">
（角色基础信息正文）
</character_basic>
```

或用 `---` 开头 + 键值结构。**Electron 工具新增的 MVU 条目正文是纯 YAML / 纯模板文本**，不涉及上述包裹，见 [03](03_MVU实现文档.md)。

## 4. 正则脚本（Regex Script）

正则脚本是"消息替换管道"。**每个 UI 元素 / 每个隐藏目标 = 一条正则规则**。

### 4.1 字段定义

```jsonc
{
  "id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",  // UUID，必须唯一
  "scriptName": "正则名",
  "findRegex": "<StatusPlaceHolderImpl/>",       // 匹配表达式（或 /正则/flags）
  "replaceString": "",                           // 替换字符串
  "trimStrings": [],                             // 先修剪的字符串
  "placement": [2],                              // 作用范围
  "disabled": false,
  "markdownOnly": false,                          // 仅格式显示（改玩家看到的）
  "promptOnly": true,                             // 仅格式提示词（改发给 AI 的）
  "runOnEdit": true,
  "substituteRegex": 0,
  "minDepth": null,
  "maxDepth": null
}
```

### 4.2 关键字段语义

| 字段 | 说明 |
|------|------|
| `placement` | 1=用户输入, 2=AI 输出, 3=快捷命令, 4=世界书, 5=推理 |
| `promptOnly` | `true` 时在**发送给 AI 前**替换（控制 AI 看到什么），不改变显示 |
| `markdownOnly` | `true` 时在**渲染到前端时**替换（控制玩家看到什么），不改变底层消息 |
| `substituteRegex` | 0=不改变原文本（推荐），1/2=替换到消息本体 |
| `runOnEdit` | 编辑消息时是否触发；状态栏类 `true`，变量更新类 `false` |
| `minDepth`/`maxDepth` | 深度限制（1=最新楼层），null=不限 |

### 4.3 核心模式：隐藏 + 替换配对

**每个界面元素需要两条正则**：

| 角色 | 字段组合 | 作用 |
|------|---------|------|
| **隐藏** | `promptOnly: true`, `markdownOnly: false`, `replaceString: ""` | 把占位符从发给 AI 的上下文里删掉 |
| **替换** | `markdownOnly: true`, `promptOnly: false`, `replaceString` 或 HTML | 把占位符换成玩家看到的界面 |

以状态栏为例（MVU 标配的"对 AI 隐藏状态栏" + "状态栏界面"）：

```jsonc
// 对AI隐藏状态栏 —— 从 AI 上下文移除占位符
{
  "findRegex": "<StatusPlaceHolderImpl/>",
  "replaceString": "",
  "placement": [2],
  "promptOnly": true, "markdownOnly": false, "runOnEdit": true, "substituteRegex": 0
}
// 状态栏界面 —— 在前端把占位符换成 HTML
{
  "findRegex": "<StatusPlaceHolderImpl/>",
  "replaceString": "```html\n<body>...</body>\n```",
  "placement": [2],
  "promptOnly": false, "markdownOnly": true, "runOnEdit": true, "substituteRegex": 0
}
```

> **Electron 工具注入时直接写 `replaceString`（内联 HTML 字符串）即可**，不必走
> `replace_file` 文件机制——那只是 `tavern-cards-forge` 项目目录的组织方式。

### 4.4 带捕获组的正则（变量更新美化类）

解析 `<update>...</update>` 内容时用捕获组 `$2` 提取正文：

```
/<(update(?:variable)?)>\s*((?:(?!<\1>).)*)\s*<\/\1>/gsi
```

- 完整版：`变量更新美化` —— 匹配已闭合的完整标签，`$2` = 内容
- 未闭合版：`变量更新中美化` —— 用负向前瞻 `(?!.*<\/\1>)` 匹配还在生成的标签
- 隐藏版（同时匹配两种状态）：

```
/<\s*(update(?:variable)?)>(?:(?!.*<\/\1>)(?:(?!<\1>).)*$|(?:(?!<\1>).)*<\/\1?>)/gsi
```

> JSON 中反斜杠要双写：`\s` → `\\s`，`\1` → `\\1`，`\/` → `\\/`。
> 这也是为什么 JSON 文件里的正则看起来全是 `\\`。

### 4.5 正则概念速查

| 概念 | 写法 | 说明 |
|------|------|------|
| 捕获组 | `(pattern)` | `$1` `$2` 引用 |
| 非捕获组 | `(?:pattern)` | 只分组不捕获 |
| 反向引用 | `\1` | 引用第 1 个捕获组的匹配文本 |
| 负向前瞻 | `(?!pattern)` | 后面不能匹配 |
| 任意字符含换行 | `.` + `s` flag | dotall |
| 全局 | `g` | 匹配所有 |
| 忽略大小写 | `i` | 大小写不敏感 |

## 5. 酒馆助手脚本（Tavern-Helper Script）

酒馆助手（Tavern-Helper，仓库名 JS-Slash-Runner）是渲染 HTML 界面、执行脚本的扩展。
脚本运行在 **iframe** 中，分为**消息楼层 iframe**（渲染界面）和**全局脚本 iframe**（后台逻辑）。

### 5.1 脚本嵌入角色卡的结构

角色卡 JSON 中：

```jsonc
{
  "extensions": {
    "tavern_helper": {
      "scripts": {
        "MVU": {           // ← 脚本名（key）
          "type": "script",
          "content": "import 'https://.../MagVarUpdate/artifact/bundle.js'",  // 脚本源码
          "enabled": true,
          "id": "d0311ca6-5e9a-498e-a777-f74dc4dc6b12",   // 唯一 id
          "info": "",
          "button": {
            "enabled": true,
            "buttons": [ { "name": "重新处理变量", "visible": true } ]
          },
          "data": {}
        }
      },
      "variables": {}       // 角色卡级变量
    }
  }
}
```

> 脚本 `content` 中可以直接写 ESM import（如
> `import 'https://testingcf.jsdelivr.net/gh/MagicalAstrogy/MagVarUpdate/artifact/bundle.js'`），
> 酒馆助手在脚本 iframe 的 `<script type="module">` 里执行它。

### 5.2 两种 iframe

| 维度 | 消息楼层 iframe | 全局脚本 iframe |
|------|----------------|-----------------|
| 名字 | `TH-message--{message_id}--{swipe_id}` | `TH-script--{script_id}--{名称}` |
| 用途 | 渲染状态栏等前端 UI | 后台逻辑、事件监听 |
| 变量读取链 | `global→character→chat→message[0..当前]`（含楼层变量） | `global→character→script→chat`（**不含楼层变量**） |
| `getCurrentMessageId()` | ✅ | ❌（报错） |
| `getScriptId()` | ❌ | ✅ |

> **脚本 iframe 里 `getAllVariables()` 读不到 message 楼层变量**，必须
> `getVariables({ type: 'message', message_id: ... })`。消息楼层 iframe 没有 `cleanup_protector`，
> `window.parent` 可直接访问但残留不托底，优先用官方 API。

### 5.3 预注入全局变量

脚本/界面 iframe 中**直接可用**，无需 import：

| 全局 | 来源 | 说明 |
|------|------|------|
| `Vue` / `VueRouter` | CDN 注入 | 前端框架 |
| `$` / `jQuery` | 继承 parent | DOM 操作 |
| `_` | 继承 parent | lodash |
| `showdown` / `toastr` / `YAML` | 继承 parent | 工具库 |
| `z` | 酒馆助手注入 | zod v4 |
| `SillyTavern` | 代理 getter | 每次访问返回**新对象**（不能缓存引用比对） |
| `TavernHelper` | 从 parent 拷贝 | 全部酒馆助手 API 命名空间 |
| `Mvu` | 条件性代理 | **必须先 `await waitGlobalInitialized('Mvu')`** |

### 5.4 加载 / 卸载时机

```js
// 正确：用 jQuery 就绪回调，禁止 DOMContentLoaded（load 动态注入时不会触发）
$(() => { toastr.success('加载成功'); });

// 正确：用 pagehide 而不是 unload
$(window).on('pagehide', () => { /* 清理 */ });

// 错误兜底：关键函数用 errorCatched 包裹
$(errorCatched(init));
```

## 6. 宏（Macro）

宏是运行时替换的文本占位符。

### 6.1 SillyTavern 内建宏

| 宏 | 说明 |
|----|------|
| `{{user}}` / `<user>` | 玩家名 |
| `{{char}}` | 角色名 |
| `{{lastMessageId}}` | 最新楼层 id |
| `{{time}}` `{{date}}` | 时间日期 |

> **世界书条目内推荐 `<user>` 而非 `{{user}}`**：双花括号会破坏 YAML 解析，导致文件后缀从 `.yaml` 回退 `.txt`。

### 6.2 酒馆助手注册宏

`{{format_message_variable::路径}}` —— 把 MVU 变量值替换进文本：

- `{{format_message_variable::stat_data}}` → 全部变量（YAML）
- `{{format_message_variable::stat_data.白娅.依存度}}` → 只显示值
- `$` 前缀变量不会被此宏展示

## 7. EJS 提示词模板

世界书条目正文里可用 EJS 做条件渲染（锦上添花，非 MVU 必需）。

```ejs
<%_ if (getvar('stat_data.白娅.依存度') < 30) { _%>
低依存度时的提示词
<%_ } else { _%>
高依存度时的提示词
<%_ } _%>
```

常用函数：

| 函数 | 用途 |
|------|------|
| `getvar('stat_data.路径')` | 取变量 |
| `getvar('stat_data.路径', { defaults: 0 })` | 取变量，缺省兜底 |
| `print('文本')` | 在代码块内输出 |
| `print(await getwi('条目名'))` | 输出其他条目内容 |
| `matchChatMessages(['关键词'])` | 检测最近 2 楼关键词 |
| `<%= 表达式 %>` | 值嵌入 |

> **制作时禁用酒馆助手宏与提示词模板**（看到原始代码），**游玩时启用**。

## 8. 角色卡的外部形态：PNG 与 JSON

给纯文字卡加东西时，需要先**解包**（读入 JSON），改完**打包**（写回 PNG/JSON）。

### 8.1 解包（unpack）

- PNG → 读 `chara` tEXt chunk → JSON.parse → 得到角色卡 JSON
- JSON → 直接读
- 判定世界书：JSON 无 `spec` 而有 `entries` → 独立世界书（扁平格式，字段名不同，见 [06](06_构建工具文档.md) 的格式映射表）

### 8.2 打包（pack）

- 无头像 → 输出 JSON（`spec: "chara_card_v2"`）
- 有头像 → 输出 PNG（头像像素 + `chara` chunk）

### 8.3 JSON 与 PNG 的选型

| 需求 | 选型 |
|------|------|
| 工具内部处理 | 一律先转 JSON 对象处理 |
| 输出到玩家 | 有头像给 PNG，无头像给 JSON |

## 9. 给纯文字卡加东西的本质

把所有改动归结为一句话：**读取角色卡 JSON → 修改 `data` 下的三个区域 → 写回**。
